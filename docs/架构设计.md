- 可持久化，数据安全

**Caffeine**
- 比Guava Cache性能高3倍

## 4. 数据库设计

### 4.1 核心表结构

#### 用户表 (user)

```sql
CREATE TABLE `user` (
  `id` BIGINT PRIMARY KEY AUTO_INCREMENT,
  `username` VARCHAR(50) UNIQUE NOT NULL,
  `password` VARCHAR(255) NOT NULL,
  `email` VARCHAR(100) UNIQUE NOT NULL,
  `total_score` INT DEFAULT 0,
  `solved_count` INT DEFAULT 0,
  `direction` VARCHAR(20),
  `role` VARCHAR(20) DEFAULT 'USER',
  -- 索引设计
  INDEX idx_total_score (total_score DESC),
  INDEX idx_direction (direction)
);
```

**索引说明**:
- `idx_total_score`: 排行榜查询优化
- `idx_direction`: 方向筛选优化

#### 题目表 (problem)

```sql
CREATE TABLE `problem` (
  `id` BIGINT PRIMARY KEY AUTO_INCREMENT,
  `title` VARCHAR(200) NOT NULL,
  `type` VARCHAR(20) NOT NULL,
  `direction` VARCHAR(20) NOT NULL,
  `base_score` INT NOT NULL,
  `current_score` INT NOT NULL,
  `solved_count` INT DEFAULT 0,
  -- 索引设计
  INDEX idx_direction_difficulty (direction, difficulty),
  INDEX idx_type (type)
);
```

#### 提交记录表 (submission)

```sql
CREATE TABLE `submission` (
  `id` BIGINT PRIMARY KEY AUTO_INCREMENT,
  `user_id` BIGINT NOT NULL,
  `problem_id` BIGINT NOT NULL,
  `status` VARCHAR(20) NOT NULL,
  `score` INT DEFAULT 0,
  -- 唯一索引：防止重复提交
  UNIQUE KEY uk_user_problem (user_id, problem_id, deleted)
);
```

```
┌────────────┐
│    User    │
│  (用户表)   │
└──────┬─────┘
       │ 1
       │
       │ N
┌──────▼─────────┐         ┌─────────────┐
│  Submission    │    N:1  │   Problem   │
```

### 4.3 数据库优化策略

**索引优化**
```sql
-- 1. 联合索引：方向+难度筛选
ALTER TABLE problem ADD INDEX idx_dir_diff (direction, difficulty);

-- 2. 覆盖索引：排行榜查询
ALTER TABLE user ADD INDEX idx_rank 
  (total_score DESC, solved_count DESC, id);
```

**查询优化**
```sql
-- 优化前：全表扫描
SELECT * FROM user ORDER BY total_score DESC LIMIT 50;

-- 优化后：使用索引
SELECT id, username, total_score FROM user 
  WHERE deleted = 0 
  ORDER BY total_score DESC, id ASC 
  LIMIT 50;
```

## 5. 缓存架构

### 5.1 多级缓存设计

```
┌──────────────────────────────────────────────────┐
│                   应用请求                        │
└───────────────────┬──────────────────────────────┘
                    │
      ┌─────────────▼─────────────┐
      │  L1: Caffeine本地缓存      │
      │  - 容量: 1000条            │
      │  - 过期: 30分钟            │
      │  - 命中率: ~80%            │
      └─────────────┬─────────────┘
                    │ Miss
      ┌─────────────▼─────────────┐
      │  L2: Redis分布式缓存       │
      │  - 过期: 1小时             │
      │  - 命中率: ~15%            │
      └─────────────┬─────────────┘
                    │ Miss
      ┌─────────────▼─────────────┐
      │  L3: MySQL数据库           │
      │  - 持久化存储              │
      │  - 命中率: ~5%             │
      └───────────────────────────┘
```

### 5.2 缓存策略

| 数据类型 | 缓存位置 | 过期时间 | 更新策略 |
|---------|---------|---------|---------|
| 用户信息 | Redis | 1小时 | 主动更新 |
| 题目详情 | Caffeine + Redis | 30分钟 | 主动失效 |
| 题目列表 | Redis | 10分钟 | 定时刷新 |
| 排行榜 | Redis ZSet | 5分钟 | 实时更新 |
| 公告列表 | Redis | 1小时 | 主动更新 |

### 5.3 缓存一致性方案

**Cache Aside Pattern（旁路缓存）**

```java
// 读操作
public User getUser(Long id) {
    // 1. 先查本地缓存
    User user = caffeineCache.get(id);
    if (user != null) return user;
    
    // 2. 再查Redis
    user = redisCache.get("user:" + id);
    if (user != null) {
        caffeineCache.put(id, user);
        return user;
    }
    
    // 3. 最后查数据库
    user = userMapper.selectById(id);
    if (user != null) {
        redisCache.set("user:" + id, user);
        caffeineCache.put(id, user);
    }
    return user;
}

// 写操作：先更新DB，再删除缓存
public void updateUser(User user) {
    userMapper.updateById(user);
    
    // 删除缓存（延迟双删防止并发问题）
    redisCache.delete("user:" + user.getId());
    caffeineCache.invalidate(user.getId());
}
```

## 6. 性能优化方案

### 6.1 并发控制

**分布式锁（Redisson实现）**

```java
@Service
public class SubmissionService {
    
    @Autowired
    private RedissonClient redissonClient;
    
    public void submitAnswer(Long userId, Long problemId, String answer) {
        String lockKey = "lock:submit:" + userId + ":" + problemId;
        RLock lock = redissonClient.getLock(lockKey);
        
        try {
            // 尝试获取锁，最多等待3秒，锁定10秒
            if (lock.tryLock(3, 10, TimeUnit.SECONDS)) {
                // 执行业务逻辑
                doSubmit(userId, problemId, answer);
            } else {
                throw new BusinessException("系统繁忙，请稍后再试");
            }
        } finally {
            if (lock.isHeldByCurrentThread()) {
                lock.unlock();
            }
        }
    }
}
```

**使用场景**:
- ✅ 防止用户重复提交答案
- ✅ 保证积分计算原子性
- ✅ 排行榜更新互斥

### 6.2 接口限流

**令牌桶算法（Redis + Lua）**

```lua
-- Lua脚本保证原子性
local key = KEYS[1]
local limit = tonumber(ARGV[1])
local expire = tonumber(ARGV[2])

local current = tonumber(redis.call('get', key) or "0")

if current + 1 > limit then
    return 0  -- 限流
else
    redis.call('INCRBY', key, 1)
    redis.call('EXPIRE', key, expire)
    return 1  -- 放行
end
```

**限流配置**:
```java
@RateLimit(qps = 10)  // 每秒10次
public Result<?> someApi() { ... }
```

### 6.3 数据库连接池优化

**HikariCP配置**

```yaml
spring:
  datasource:
    hikari:
      minimum-idle: 5           # 最小空闲连接
      maximum-pool-size: 20     # 最大连接数
      connection-timeout: 30000 # 连接超时30秒
      idle-timeout: 600000      # 空闲超时10分钟
      max-lifetime: 1800000     # 最大生命周期30分钟
```

### 7.2 核心安全机制

**1. JWT认证流程**
```
用户登录 → 验证密码 → 生成JWT → 存储Redis
    ↓
后续请求携带Token → JWT过滤器解析 → 验证有效性
    ↓
设置SecurityContext → 业务处理
```

**2. 防重放攻击**
```java
// 在JWT中加入时间戳和nonce
String token = Jwts.builder()
    .setClaims(claims)
    .claim("timestamp", System.currentTimeMillis())
    .claim("nonce", UUID.randomUUID().toString())
    .signWith(key)
    .compact();
```

**3. IP黑名单**
```java
// 检测异常行为自动封禁
if (failedAttempts > 5) {
    ipBlacklistService.addToBlacklist(ip, 1, TimeUnit.HOURS);
}
```
